# Промоакции Bolt/Uber: отслеживание и режим «Бонус+»

Модуль `feature-promotions` (Android) + сервис `promotions` (backend). Общая архитектура —
[architecture.md](architecture.md); скоринг — там же, раздел 4.

Ответ на вопрос «отслеживать или просто сделать режим Бонус+»: **и то, и другое, и связать их**.
Режим «Бонус+» без знания условий акции — слепой: он не знает, сколько поездок осталось, успевает ли
водитель, не рушит ли отказ показатель принятия. А отслеживание без режима — просто календарь. Поэтому
модуль: (1) собирает условия акций из экранов приложений, (2) считает **предельную ценность бонуса на
одну поездку** и (3) подмешивает её в скоринг, автоматически включая «Бонус+», когда это выгодно.

## 1. Какие акции бывают (по реальным экранам)

| Тип | Платформа | Пример с экрана | Формула выплаты | Условия |
|-----|-----------|-----------------|-----------------|---------|
| **Quest / Kampania** — бонус за N поездок в окне | Uber «Quest» (Zadanie 1/2), Bolt «Kampanie» | Uber: 30 поездок → 60 zł, +10 → +20 zł (ступени); Bolt: 26 paź 04:00–08:59 — 10 поездок → 110 zł; 28 paź 05:00–07:59 — 6 → 58 zł; 31 paź 00:00–05:59 — 12 → 132 zł | фиксированная сумма при достижении порога, ступени накапливаются | **показатель принятия** (Uber 25 %; Bolt «wskaźnik akceptacji kwalifikujących się» — порог в деталях), категории, город; у Uber — надо **выбрать** задание, у Bolt — часто опт-ин |
| **Boost+** — доплата за активный час в зоне | Uber «Odkrywaj» | 7:00–8:00 +18 zł / активный час, 8:00–9:00 +14 zł, 16:00–17:00 …; полигон Przymorze/Oliwa | `rate × (время от принятия до высадки) / 60` за каждую поездку, начатую в зоне и окне («na podstawie szacowanego czasu od przyjęcia zamówienia do dostawy») | нужно **зарегистрироваться** на слот («Zarejestruj się»), только поездки, в зоне подачи |
| Сурж / множители / зоны повышенного спроса | обе | в цене карточки | уже в `price` | — |
| Пер-поездочные надбавки | Uber Priority «+4,59 zł», Bolt «Premium» | в карточке | уже парсятся как `bonus` | — |
| Серии (streak) — N принятых подряд | Uber «Seria» (есть не везде) | «3 подряд → +15 zł» | фиксированная за серию | отказ обнуляет серию |
| Гарантия дохода | Uber «Gwarancja» | «минимум 300 zł за 10 часов онлайн» | доплата до гарантии | онлайн-часы, принятие, иногда поездки |
| Бонусы за часы онлайн | Bolt | «+5 zł за каждый час онлайн с 22 до 6» | `rate × часы` | онлайн, иногда мин. поездок |

Единая модель:

```kotlin
data class Promotion(
    val id: String, val platform: Platform,
    val kind: Kind,                     // QUEST | BOOST_ZONE | STREAK | GUARANTEE | ONLINE_HOURS
    val title: String,
    val window: ClosedRange<Instant>,   // для Quest на неделю — вся неделя; для Bolt кампании — часы
    val regionId: String?, val zone: Polygon?,          // Boost+
    val tiers: List<Tier>,              // (trips_required, reward) — ступени
    val ratePerHour: Money?,            // Boost+ / online hours
    val minAcceptanceRate: Double?,     // 0.25 у Uber Quest; Bolt — из деталей
    val eligibleProducts: Set<String>?, // «Wszystkie kategorie» / «Tylko przejazdy»
    val requiresOptIn: Boolean, val optedIn: Boolean?,
    val source: Source,                 // SCREEN | NOTIFICATION | MANUAL | COMMUNITY
    val confidence: Double, val capturedAt: Instant,
)
data class PromotionProgress(          // обновляется по фактам
    val promotionId: String, val tripsDone: Int, val tripsOffered: Int, val tripsAccepted: Int,
    val acceptanceRate: Double, val earnedSoFar: Money, val updatedAt: Instant,
)
```

## 2. Как отслеживать

Ни Bolt, ни Uber не дают API для водителей. Пять каналов, от самого надёжного к резервному:

### 2.1 Чтение экранов акций (основной)

Тот же `AccessibilityService`, что читает карточки заказов, распознаёт экраны акций, **когда водитель
их открывает** (ничего не нажимая за него): Uber — «Odkrywaj», «Quest / Zadania», «Promocje»,
«Przychód → Promocje»; Bolt — «Kampanie», «Bonusy». Якоря: заголовок экрана + повторяющиеся блоки с
числом поездок и суммой.

Экстракторы по форме данных (без привязки к языку, как у парсера карточек):

| Поле | Паттерн | Пример |
|------|---------|--------|
| Ступень Quest | `(\d{1,3})\s*(przejazd|поезд|trip)\w*.*?(\+?\d{1,4})\s*(zł|pln|€)` или две строки рядом «Liczba przejazdów: 30» / «60 zł» | 30 → 60; `+10` → `+20` (ступень) |
| Показатель принятия | `(akceptacji|принятия|acceptance)\D{0,20}(\d{1,3})\s*%` | 25 % |
| Окно кампании | `(\d{1,2}) (paź|lis|…|окт|ноя|…)[,.]?\s*(\d{1,2}):(\d{2})\s*[–-]\s*…` | 26 paź 04:00 – 26 paź 08:59 |
| Boost+ слот | `(\d{1,2}):(\d{2})\s*[–-]\s*(\d{1,2}):(\d{2})` + `(\d{1,3})\s*zł.*?(godzin|час|hour)` | 7:00–8:00, 18 zł |
| Boost+ зона | полигон с экрана не читается; берём **название района** из миниатюры/заголовка (OCR по миниатюре карты — опционально) либо просим водителя один раз обвести зону на карте приложения; зона кэшируется по названию | «Przymorze / Oliwa, 468» |
| Статус | `Zarejestruj się / Zarejestrowano`, `Wybierz zadanie / Wybrano` | optedIn |
| Прогресс | `(\d{1,3})\s*/\s*(\d{1,3})` или «Ukończono: 7 z 10» | 7/10 |

Многоязычные словари (PL/RU/EN/UK) — такие же, как в парсере карточек, доставляются с сервера.
Нераспознанные экраны → маскированный `raw_sample` → LLM-кандидат правила.

Чтобы данные были свежими, приложение **напоминает** открыть экран акций: при старте смены
(«Открой Kampanie в Bolt и Odkrywaj в Uber — я считаю бонусы»), и когда известная кампания
заканчивается, а новых не видно 48 часов. Опционально (при включённом `feature-autotap`) — кнопка
«Синхронизировать акции»: приложение само открывает Bolt → Kampanie и Uber → Odkrywaj по deep-link /
навигации по меню, читает и возвращается. Выключено по умолчанию, как весь автотап.

### 2.2 Уведомления платформ

Bolt и Uber присылают push «Nowa kampania: 110 zł za 10 przejazdów», «Boost+ в вашем районе».
`NotificationListenerService` уже есть — парсим текст теми же экстракторами, создаём `Promotion` с
`confidence` 0.6 и просим подтвердить деталями с экрана.

### 2.3 Сообщество (сервер)

Кампании Bolt — **региональные** («Trójmiasto», «Wszystkie kategorie»), Boost+ — зональные и общие
для всех в зоне. Если один водитель региона прочитал кампанию, сервер предлагает её остальным как
`COMMUNITY` с пометкой «проверьте, что она у вас есть». Uber Quest — **персонализированный**
(пороги 30/40 подбираются под водителя), поэтому Quest не шарится, только статистика «какие пороги
бывают».

### 2.4 Ручной ввод

Форма «Добавить акцию» с шаблонами по типам: 4–5 полей, 20 секунд. Голосом через кнопку руля вне
окна решения: «Бонус: десять поездок, сто десять злотых, до девяти утра».

### 2.5 Факт выплаты

Экран доходов (Uber «Przychód», Bolt «Zarobki») после недели показывает начисленные бонусы —
читаем для сверки: обещано / получено. Это закрывает цикл и калибрует доверие к модели.

## 3. Прогресс

`PromotionProgress` обновляется из уже существующих источников:

- поездка завершена (окно «поездка завершена» / `outcomes`) → `tripsDone++` для всех активных акций
  платформы, где поездка квалифицируется (окно, зона подачи, продукт);
- предложение показано / принято / отклонено → `tripsOffered`, `tripsAccepted`, `acceptanceRate`.
  Для Bolt предложения с тегом `NO_PENALTY_DECLINE` («Odrzucenie nie wpłynie na Wskaźnik akceptacji»)
  в знаменатель **не** идут;
- Boost+: `earnedSoFar += rate × (actual_pickup_min + actual_trip_min) / 60` для поездок из зоны.

Если экран акций показывает свой прогресс («7 z 10») — он главнее нашего счётчика (платформа могла
не засчитать поездку).

## 4. Экономика: предельная ценность бонуса на поездку

Ключевая идея: бонус превращается в **добавку к `net` каждой подходящей поездки**, и дальше работает
обычный скоринг (`R_km`, `R_h`, `E`). Никаких отдельных «если акция — брать всё».

### 4.1 Quest / Kampania

```
remaining      = trips_required_next_tier − trips_done
hours_left     = window_end − now (часы, в пределах планируемой смены)
λ_acc          = принятых поездок в час за последние 2 ч (сглажено историей этого daypart)
expected_more  = λ_acc × hours_left

feasibility    = clamp(expected_more / remaining, 0, 1.5)
P_complete     = sigmoid-образно: 0 при feasibility < 0.6, 1 при ≥ 1.2, линейно между

marginal_bonus = reward_tier × P_complete / remaining          // ценность одной поездки
```

Смысл: 110 zł за 10 поездок, сделано 6, осталось 2 часа, принимаем 2,3/ч → `expected_more 4,6`,
`remaining 4`, `feasibility 1,15` → `P ≈ 0,9` → `marginal_bonus ≈ 110 × 0,9 / 4 ≈ 25 zł` на поездку.
Короткий заказ за 9,54 zł (нетто 6,6) с бонусной добавкой 25 zł становится лучшим предложением
вечера. Если же сделано 2 и остался час → `feasibility 0,29` → `P = 0`, бонус не учитывается —
не гонимся за недостижимым.

Ступени: `remaining` и `reward` берутся до **следующей** ступени; достигнув 30 → 60 zł, считаем
следующую (+10 → +20 zł) — предельная ценность падает (2 zł/поездка), «Бонус+» сам выключится.

### 4.2 Показатель принятия — цена отказа

Отказ уменьшает `acceptanceRate`. Если после отказа показатель упадёт ниже `minAcceptanceRate +
safety_margin` (настройка, по умолчанию +5 п.п.), то отказ стоит **весь бонус** (с вероятностью
`P_complete`). Поэтому к `E` отклоняемого предложения добавляется:

```
decline_cost = P_complete × reward_remaining_total   // если отказ пробивает порог
```

Практически: при 25 % (Uber) это почти никогда не бьёт — можно отказываться от трёх из четырёх.
У Bolt порог «kwalifikujących się» обычно высокий — и там свободны только отказы с тегом
`NO_PENALTY_DECLINE`. Оверлей показывает «Принятие: 31 % (нужно ≥ 25 %)», а при опасности —
«Отказ сорвёт бонус 110 zł».

### 4.3 Boost+

```
boost_bonus = rate × (pickup_min_eff + trip_min_eff) / 60     // если подача в зоне и в слоте
```

Добавляется к `net`. Особенность: Boost+ **пропорционален времени**, поэтому он, наоборот, делает
выгодными длинные и медленные поездки из зоны — режим «коротких заказов» здесь не нужен, и модуль
этого не делает. Зато важна **позиция**: рекомендация «куда ехать» получает слагаемое «в 7:00 быть в
зоне Przymorze — +18 zł/ч к любой поездке», а высадка **вне** зоны штрафуется (`zone_factor` ниже:
следующий заказ без бонуса и надо возвращаться). Напоминание зарегистрироваться на слот за 30 минут.

### 4.4 Серии, гарантии, часы онлайн

- Streak: `marginal = reward / trips_in_streak_remaining`, отказ = потеря серии → `decline_cost = накопленное`.
- Гарантия: пока прогнозируемый доход за окно ниже гарантии, предельная ценность дополнительной
  поездки ≈ 0 (платформа доплатит), выше — обычная. Режим «не выматываться».
- Часы онлайн: добавка к стоимости часа простоя (ждать выгоднее), порог `E*` чуть выше.

## 5. Режим «Бонус+»

Это не отдельная формула, а **автоматический профиль скоринга**, который включается, когда у активной
акции `marginal_bonus ≥ bonus_mode_min_marginal` (настройка, по умолчанию 8 zł) и `P_complete ≥ 0.5`:

| Что меняется | Как |
|--------------|-----|
| `net` | `+ marginal_bonus` (Quest/серии) или `+ boost_bonus` (Boost+) для квалифицирующихся предложений |
| Цель | для Quest — максимум **поездок в час**, поэтому `α` сдвигается к времени (0.25) и короткий цикл ценится выше |
| Порог `E*` | не ниже пола `bonus_mode_floor` (настройка, по умолчанию `E` при себестоимости × 1.2): минимально выгодно, но не в убыток |
| Отказ | учитывает `decline_cost` |
| Межплатформенность | предложения платформы с активной акцией получают добавку, другой — нет; оверлей показывает, почему Uber за 9 zł предпочтительнее Bolt за 12 |
| Озвучка | «Uber, 9 злотых плюс бонус 25. Брать. Осталось 3 поездки.» |
| Автоприём | `minScoreRatio` считается уже с бонусом; дополнительное условие — `P_complete ≥ 0.7` |
| Индикатор | плашка «Бонус+ · 6/10 · 2 ч 05 мин · принятие 31 %» в оверлее и на дисплее магнитолы |

Режим выключается сам, когда акция завершена, недостижима (`P_complete` = 0) или следующая ступень
слишком дёшева. Водитель может включить/выключить вручную (кнопка руля `PLAY_PAUSE` тройное нажатие
в постоянном режиме или тумблер в уведомлении) — тогда модуль принимает заданный вручную
`marginal_bonus` из настроек («считать, что каждая поездка приносит +X zł»): это и есть «простой
Бонус+» для случаев, когда условия акции не считаны.

## 6. Планирование акций

Экран «Акции»: календарь недели с окнами кампаний (Bolt 26.10 04:00–08:59, 28.10 05:00–07:59,
31.10 00:00–05:59; Uber Boost+ слоты 7–9 и 16–17; Quest на неделю), для каждой — оценка:

```
value_per_hour = (reward × P_complete_planned + typical_net_per_hour × hours) / hours
```

где `P_complete_planned` — по истории водителя в этом daypart (сколько поездок/час он обычно делает
ночью). Планировщик отвечает: «Кампания 31.10 00:00–05:59: 12 поездок за 6 ч — ваша ночная норма
1,9/ч → 11,4, на грани; 28.10 05:00–07:59: 6 за 3 ч при утренней норме 2,8/ч — реально, +58 zł».
Для Uber Quest с выбором (30 → 60 или 40 → 80) — рекомендация по недельной истории поездок с
оценкой риска. Конфликты (Boost+ зона vs Bolt кампания в одно время) помечаются, предлагается
приоритет по `value_per_hour`.

Напоминания: за день — «завтра кампания Bolt 04:00–08:59, стоит ли вставать: +110 zł при 10 поездках,
обычно вы делаете 9–11 за это время»; за 30 мин до Boost+ — «зарегистрируйтесь на слот».

## 8. Данные

- `promotions` — модель из раздела 1, `region_id`, `driver_id` (null для community), `source`, `confidence`.
- `promotion_progress` — прогресс по водителю.
- `promotion_payouts` — обещано / получено (из экрана доходов), для доверия к модели.
- В `decisions` добавляются `marginal_bonus_applied`, `decline_cost_applied`, `bonus_mode_active`.

Отчёты ([reports.md](reports.md)): `bonus_earned`, `bonus_per_trip`, `decisions_changed_by_bonus`,
`promotions_completed / attempted`, `acceptance_rate_in_window`; инсайт «Кампания Bolt: 10/10, +110 zł;
5 коротких заказов приняты благодаря Бонус+ (без него — отказ), фактический доход за час 71 zł против 48».

## 9. Тестирование

- Юнит: `marginal_bonus` на сценариях (далеко до цели / на грани / недостижимо / ступени), `decline_cost`
  вокруг порога принятия, Boost+ с подачей внутри/вне зоны и на границе слота.
- Парсер экранов акций на фикстурах из трёх присланных скриншотов (Uber Quest, Uber Odkrywaj Boost+,
  Bolt Kampanie) + негативные (экран доходов, чат).
- Планировщик: сверка рекомендаций с историей (ретроспективно: что бы он посоветовал неделю назад и
  что вышло).
