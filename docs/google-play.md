# Google Play: что нужно, чтобы Taxi Commandos приняли

Короткий ответ: **полную версию приложения, как она спроектирована (чтение экранов Bolt/Uber/Free Now и автотап), Google Play с высокой вероятностью не примет.** Это не вопрос «хорошо заполнить анкету» — с октября 2025 политика Accessibility прямо запрещает приложениям **самостоятельно инициировать, планировать и выполнять действия** через Accessibility API. Автоприём и чтение чужих карточек — именно это.

Ниже — что блокирует публикацию, что можно выложить как **Taxi Commandos Lite**, и какие общие требования Play нужно соблюсти в любом случае.

Источники: [Use of the AccessibilityService API](https://support.google.com/googleplay/android-developer/answer/10964491), [Policy announcement 30 Oct 2025](https://support.google.com/googleplay/android-developer/answer/16550159), [Foreground service declarations](https://support.google.com/googleplay/android-developer/answer/13392821), User Data / Permissions policies.

## 1. Жёсткие блокировки полной версии

| Функция в проекте | Политика Play | Вердикт |
|-------------------|---------------|---------|
| `AccessibilityService` читает дерево Bolt/Uber/Free Now | API разрешён не только a11y-инструментам, но **нельзя** заявлять `isAccessibilityTool=true` (ассистенты, автоматизация, мониторинг — прямо в списке «не accessibility tool»). С 30.10.2025 **запрещено** автономно initiate / plan / execute действия через этот API | Автоприём — запрещён. Даже «только читаем карточку» ревьюеры обычно квалифицируют как автоматизацию / обход UI платформы |
| Автотап «Принять» | То же + Device and network abuse / обход чужого UI | Нельзя на Play |
| `MediaProjection` снимков карты спроса чужого приложения | Захват экрана других приложений без их согласия; FGS `mediaProjection` требует видео и use case «проекция на внешний дисплей», не «парсим карту Uber» | Скорее отказ |
| Оверлей поверх Bolt/Uber с вердиктом | `SYSTEM_ALERT_WINDOW` сам по себе допустим (мессенджеры, навигация), но оверлей, имитирующий UI платформы или перехватывающий нажатия, — Misleading behavior | Только свой экран / виджет, не поверх чужой кнопки «Akceptuj» |
| Назначение себя цифровым ассистентом (кнопка «голос» на руле) | Роль ассистента на Play возможна, но связка «ассистент + Accessibility» усиливает подозрение | В Lite — только MediaSession, без роли ассистента |
| Чтение уведомлений Bolt/Uber | `NotificationListener` требует декларации; чтение чужих уведомлений — чувствительные данные | Возможно в Lite при узком scope и раскрытии; детали заказа часто **не** в уведомлении |

Лгать в декларации (`isAccessibilityTool=true`, «помогаем людям с нарушениями моторики») — путь к бану аккаунта разработчика, не к публикации.

**Вывод:** канал распространения полной версии остаётся **свой APK на taxicom.app** (как в C4 / W0). Play — только если есть урезанная сборка.

## 2. Что можно выложить на Play: Taxi Commandos Lite

Сборка `app.taxicom.commandos.lite` **без** Accessibility, автотапа, MediaProjection и оверлея поверх чужих приложений.

| Остаётся на Play | Как работает без чтения экрана |
|------------------|--------------------------------|
| Аккаунт, связка устройств, кокпит-дашборд, отчёты, e-mail, Telegram | Данные приходят с CAPTURE-телефонов, где стоит полная версия (sideload), либо ручной ввод |
| План смены, события, прилёты, «куда ехать», советник аэропорта Uber (по OpenSky, не по экрану очереди) | Серверные коллекторы |
| «Еду к…», настройки скоринга, расходы/топливо | Локально |
| Кнопки руля через MediaSession (AVRCP) | Без HFP-роли ассистента |
| Push, графики, PDF | Как спроектировано |

| Только sideload (полная) | |
|--------------------------|--|
| Чтение карточек, автотап, тихий игнор в поездке, сурж со снимка карты, прогресс Quest с экрана, ETR очереди Uber с экрана, Arrived-таймер с окна платформы | |

Практичная схема: водитель ставит **полную** на телефоны с Bolt/Uber/Free Now (taxicom.app), **Lite с Play** — на планшет-кокпит. Кокпиту Accessibility не нужен.

Нельзя в листинге Play обещать «принимаем заказы за вас» или показывать скриншоты автотапа — это будет расхождение store listing vs APK (Misleading).

## 3. Общие условия Play — для Lite и на случай повторной подачи

Эти пункты обязательны для **любого** приложения в Store, независимо от Accessibility.

### 3.1 Аккаунт и тест

- Платный аккаунт разработчика, верификация личности / организации.
- С ноября 2023 новые персональные аккаунты: **закрытый тест, ≥ 12 тестировщиков, ≥ 14 дней** до продакшена.
- Политика конфиденциальности на `https://taxicom.app/privacy` (и в приложении).
- Data safety form: какие данные, зачем, шаринг, шифрование, удаление.
- **Удаление аккаунта в приложении и на сайте** (уже в auth) — требование Play.
- Возрастной рейтинг IARC; не «Families».
- Целевой SDK: актуальный (на 2026 — API 35+); 64-bit.

### 3.2 Разрешения — только под заявленную функцию

| Разрешение | На Play | Как декларировать |
|------------|---------|-------------------|
| Геолокация, в т.ч. фон | Да, если ядро — смена и «куда ехать» | Prominent disclosure до запроса; фон — отдельное обоснование («трек смены, волны») |
| Уведомления | Да | FCM, алерты принятия |
| Bluetooth (`CONNECT`) | Да | Руль, имя магнитолы |
| `FOREGROUND_SERVICE_LOCATION` / `_MEDIA_PLAYBACK` | Да | Декларация FGS в Console: описание, что будет если отложить/прервать, **видео** каждой функции |
| `FOREGROUND_SERVICE_MEDIA_PROJECTION` | Нет в Lite | В полной — не для Play |
| `BIND_ACCESSIBILITY_SERVICE` | Нет в Lite | В полной — не для Play |
| `SYSTEM_ALERT_WINDOW` | Избегать в Lite | Свой UI, не оверлей на Bolt |
| `QUERY_ALL_PACKAGES` | Не использовать | В `<queries>` только пакеты Bolt/Uber/Free Now |
| Точный список установленных приложений | Нельзя | — |

Видео для FGS: пользователь в приложении запускает смену / подключает BT — не «системные настройки».

### 3.3 Данные и магазинные тексты

- Отдельный экран согласия **до** запроса чувствительных разрешений (не только в политике).
- Не собирать имена пассажиров на сервер (уже так).
- Не использовать логотипы и товарные знаки Uber/Bolt/Free Now как свои; в описании: «неофициальный помощник, не аффилированы».
- Не обещать обход правил платформ.
- Data Safety = фактическому коду (иначе reject после ревью обновления).

### 3.4 Поведение и контент

- Нет скрытых сервисов, нет кликджекинга.
- Обновления не добавляют Accessibility «тихо» — ревью сравнивает с прошлой версией.
- EU: DSA / контакт издателя на витрине.

## 4. Если всё же подавать полную версию (не рекомендуется)

Минимальный набор, без которого форму даже не примут к рассмотрению:

1. Play Console → декларация Accessibility: **не** accessibility tool; точное описание «читаем UI водительских приложений, чтобы показать оценку; тап только после действия пользователя».
2. In-app prominent disclosure + checkbox **отдельно** от остальных согласий, на нормальном пути запуска, не в меню.
3. Автоприём **выключен в Play-сборке** (product flavor): иначе Oct 2025 policy — прямой запрет.
4. Видео: онбординг раскрытия, включение Accessibility в настройках системы, оценка заказа **без** автотапа.
5. Готовность к отказу и апелляции; запасной канал — APK.

Даже при выполнении 1–5 отказ остаётся наиболее вероятным исходом.

## 5. Решение для Taxi Commandos

| Канал | Что | Зачем |
|-------|-----|--------|
| **taxicom.app** (основной) | Полный APK, автообновление | Единственный способ легально (относительно Play) отдать захват и автотап |
| **Google Play** (опционально, после W4) | Flavor Lite: дашборд, отчёты, события, план, руль AVRCP, логин | Доверие, обновления, находят по имени; кокпит на планшете |
| Один `applicationId` нельзя делить | Lite = `app.taxicom.commandos.lite` | Иначе Play снимет приложение, когда в обновлении появится Accessibility |

В декомпозиции: задача **T0.1.4** остаётся «APK на taxicom.app»; публикация Lite — отдельная задача **T4.9** после стабильного дашборда, не блокер волн W0–W4.
